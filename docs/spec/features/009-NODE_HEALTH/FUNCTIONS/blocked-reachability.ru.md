# Проверка заблокированных сайтов — периодическое подтверждение, что заблокированное открывается через туннель

Opt-in таймер: пока туннель подключён, открывает через работающее ядро
несколько сайтов из российских списков блокировок и предупреждает, если не
ответил ни один. Ловит ситуацию «туннель Connected, а заблокированное не
открывается» (например, DPI режет поток).

| Поле | Значение |
|------|----------|
| Фича | [009-NODE_HEALTH](../FEATURE.ru.md) |
| Обещания | P18 |
| Состояние | ✅ реализовано, 05.11.2026 ([721](../../../tasks/721-blocked-reachability-check.md)) |

## Что делает

Раз в интервал берёт несколько хостов из списков блокировок, шлёт каждому
один HTTPS-запрос через работающее ядро (узел адресуется тегом `route.final`,
тот же механизм, что у диагностики узла P13) и фиксирует итог: успех, если
ответил **хотя бы один**. На провал реагирует по выбору пользователя:
уведомление (по умолчанию), сброс сети ядра или переподключение.

## Параметры

Настройки приложения → Диагностика → «Проверка заблокированных сайтов».

| Настройка | Значения | Дефолт |
|-----------|----------|--------|
| Проверять заблокированные сайты | вкл / выкл | **выкл** |
| Интервал | 5 / 15 / 30 / 60 мин | 15 мин |
| Сайтов за проверку | 3 / 4 / 5 | 3 |
| Таймаут на сайт | 3 / 5 / 10 с | 5 с |
| При провале | Только уведомить / Сбросить сеть / Переподключить | Только уведомить |
| Не проверять при выключенном экране | вкл / выкл | вкл |

Фиксированные значения: первая проверка — через 60 с после Connected; списки
обновляются условным GET раз в 168 ч (как пресеты runetfreedom в шаблоне).

Источники (runetfreedom, бинарные rule-set'ы sing-box):
`geosite-ru-blocked.srs` (домены) и `geoip-ru-blocked-community.srs`
(IP-диапазоны). В пресеты маршрутизации они **не** добавляются: проверка
пользуется ими сама, в том же кэше `rule_sets/` под префиксом id
`reachability__` (сиротами не чистятся).

## Входы / Выходы

**Входы:** состояние туннеля; `route.final` работающего конфига; состояние
экрана; два rule-set'а; ответ ядра `getURLViaOutbound`.

**Выходы:** строка статуса в настройках («<когда>: ответили N из M» / «не
ответил ни один из M» / почему пропущена последняя проверка); строка
`[reachability]` в журнале приложения ([013-DIAGNOSTICS](../../013-DIAGNOSTICS/FEATURE.ru.md));
события автоматизации `REACHABILITY_FAILED` / `REACHABILITY_RESTORED` (Health,
[014-AUTOMATION](../../014-AUTOMATION/FUNCTIONS/outbound-events.ru.md)); Debug API
`GET|PUT /settings/reachability`, `POST /action/reachability-check`; на
провал — уведомление, `resetNetwork` или переподключение.

## Правила и инварианты

- **По умолчанию выключено.** Работает, только пока туннель Connected; любой
  переход в down (явный Stop, ошибка, revoke, вердикт heartbeat) отменяет
  таймер и запланированную реакцию.
- **Через ядро, не через процесс приложения.** Запрос идёт в live-ядро по тегу
  `route.final`; активный селектор не переключается, приложение сокетов не
  открывает. `route.final = direct-out` — проверка пропускается (`no_route`):
  прямой маршрут ничего не доказывает.
- **Кандидаты.** Из geosite — только `domain` и `domain_suffix` (суффикс
  проверяется как хост); `domain_keyword` и `domain_regex` отбрасываются, как и
  имена без точки, с маской и не-ASCII. geoip — вторичный источник: только
  IPv4-диапазоны до 4 адресов; адрес попадает в выборку, только если на нём
  уже была успешная проверка или хостов меньше размера выборки. Список
  кандидатов после разбора кэшируется на диске и разбирается заново только при
  смене файла rule-set'а.
- **Выборка.** N случайных целей за проверку; цели прошлой проверки в
  следующую не попадают, пока кандидатов хватает.
- **Вердикт.** Цель доступна при любом HTTP-статусе (как P13) или при ошибке
  сертификата (TLS handshake состоялся — сервер ответил); таймаут, сброс, EOF —
  недоступна. Провал — только если не ответил **ни один** из N.
- **Реакция.** `resetNetwork` / переподключение — не чаще раза за интервал и
  только если туннель всё ещё Connected и не был остановлен за время проверки
  (P12 из 010: явный Stop не воскрешается). Уведомление — один раз на серию
  провалов; первый успех после провала снимает его и шлёт
  `REACHABILITY_RESTORED`.
- **Экран выключен.** При включённой опции (по умолчанию) проверка при
  выключенном экране пропускается (`screen_off`), следующая планируется как
  обычно.
- **Без адресов серверов** в событиях, журнале и уведомлениях (P14 из 014): в
  событиях — только счётчики и имя реакции; тексты ошибок ядра в журнале
  проходят маскирование адресов.

## Границы

- Работает в Flutter-движке приложения: если процесс убит, а туннель живёт в
  сервисе, проверки останавливаются до следующего открытия приложения.
- Живой маршрут с правилами и sniff не проверяется — только аутбаунд
  `route.final` (граница kernel SPEC 058 §5, как у P13).
- IP-цель проверяется HTTPS-запросом на адрес; сервер, рвущий соединения без
  SNI, считается недоступным — поэтому IP только вторичный источник.
- Списки внешние (runetfreedom); их содержимое и доступность — не наши. Без
  обоих списков проверка пропускается (`no_candidates`).
