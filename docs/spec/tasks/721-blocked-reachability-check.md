## Problem

Туннель бывает Connected, а заблокированное не открывается: DPI режет поток
до узла, узел жив для URLTest (`generate_204` на незаблокированном адресе), но
полезный трафик не идёт. Пользователь узнаёт об этом сам, открыв сайт.
Нужна редкая проверка, что через **активный туннель** открывается хотя бы один
ресурс из списков блокировок, и настраиваемая реакция на провал.

## Diagnosis

- **Почему это не «health-watchdog», от которого отказались.** §042F (Won't-fix)
  и §088 отвергли постоянный пробник с эскалацией ради батареи; в
  010 → Boundaries это записано как решение владельца. Новая фича отличается
  по всем пунктам, ради которых отказались:
  - строго opt-in, по умолчанию выключена;
  - редкий таймер (5–60 мин, дефолт 15), а не секундный heartbeat;
  - живёт только при Connected и по умолчанию молчит при выключенном экране;
  - без лестницы эскалации: одна реакция, выбранная пользователем, не чаще раза
    за интервал; дефолт — только уведомление.
- **Через что проверять.** Сокет из процесса приложения ничего не доказывает
  про туннель (split-tunnel, исключение собственного пакета). Есть готовый путь
  §392 / P13: `getURLViaOutbound` в live-ядро по тегу — selector не трогается.
  Заблокированный трафик уходит в `route.final` (ru-direct и прочие пресеты
  забирают только своё), поэтому тег — `RouteConfig.finalTag` работающего
  конфига; `direct-out` — проверять нечего.
  Ограничение kernel SPEC 058 §5 «фоновые обходы списка запрещены» — про обход
  узлов; здесь один тег и явное согласие пользователя (opt-in).
- **Источники — не списки сайтов.** Разбор реальных файлов (05.11.2026):
  `geosite-ru-blocked.srs` — 1 правило, 73 515 `domain_suffix`, keyword/regex
  нет (фильтр всё равно нужен на будущее); `geoip-ru-blocked-community.srs` —
  840 IPv4/IPv6-диапазонов, среди них точечные `/32`.
- **Формат `.srs`.** Готового парсера в `lib/` нет, ядро разбирать не умеет
  через RPC. Формат взят из исходников sing-box (`common/srs/binary.go`,
  `ip_set.go`) и sing (`common/domain/set.go`, `matcher.go`): `SRS` + версия +
  zlib; домены — succinct-trie (LOUDS) перевёрнутых имён, суффиксы с меткой
  `\r` (v1 legacy, `\r.x` + `x`) или `\n` (v2+). Прототип на Python и Dart-порт
  дали на реальном файле одно и то же.
- **Пресеты.** Наборы в `presets.json` не добавляются: маршрутизация
  заблокированного через них — отдельное продуктовое решение, а пресеты
  меняются только через контракт (`docs/CONTRACT.md`). Проверка качает их сама
  существующим `RuleSetDownloader` (условный GET, TTL 168 ч как у пресетов
  runetfreedom).

## Solution

Владелец — **009-NODE_HEALTH**: это проверка здоровья пути через узел тем же
механизмом, что P13, и с той же семантикой «любой HTTP-статус — ответ».
010 хранит только границу (Boundaries) и правило P12, которому подчиняется
реакция.

Код (`app/lib/services/reachability/`):

- `srs_reader.dart` — чистый разбор `.srs` (все типы элементов правил
  читаются или пропускаются; домены — обход trie как `Matcher.Dump()`).
- `reachability_logic.dart` — чистая логика: кандидаты (`domain` +
  `domain_suffix`, keyword/regex отброшены; geoip — IPv4-диапазоны ≤ 4 адресов),
  выборка с ротацией (цели прошлой проверки подряд не повторяются; IP только из
  успешных или при нехватке хостов), вердикт «хотя бы один из N» (HTTP-статус
  или ошибка сертификата = доступно), ограничитель реакций (раз за интервал,
  эпоха Stop).
- `reachability_monitor.dart` — оркестратор: настройки (vars
  `reachability_*`), таймер (60 с после Connected, затем интервал), гейты
  (вкл, Connected, экран), загрузка наборов и дисковый кэш разобранных
  кандидатов (`reachability_candidates.json`, разбор в `Isolate.run`), запросы
  через `CcChannel.getUrlViaOutbound`, реакции, журнал `[reachability]`,
  события.
- Связь с туннелем — `HomeController`: `bind()` в `init()`,
  `onTunnelConnected()` на переход в connected (не на дубль),
  `onTunnelDown()` в disconnected/revoked-ветке и в `_onTunnelDead`.
- UI — `ReachabilityIsland` во вкладке App Settings → Diagnostics.
- Уведомление и состояние экрана — `VpnPlugin`: `isScreenInteractive`
  (`PowerManager.isInteractive`), `showReachabilityAlert` /
  `cancelReachabilityAlert` (`ServiceNotification`, свой id 3 — не затирает
  ошибку старта id 2; тексты локализует Dart).
- События — `REACHABILITY_FAILED {checked, action}` и
  `REACHABILITY_RESTORED {checked, reachable}` в категории Health; тумблер Health
  вернулся во вкладку Automation (§605 убирал его как пустой). `docs/AUTOMATION.md`
  (+ `.ru.md`) обновлены — публичный API.
- Debug API — `GET|PUT /settings/reachability`, `POST /action/reachability-check`
  (`help.dart`, `docs/api/debug-api-reference.md`).
- `RuleSetDownloader.pruneOrphans` не трогает id с префиксом `reachability__`.
- Строки UI — через `getLocalText`, переводы в `ru/ui.json` и `zh/ui.json`.

## Risks and edge cases

- **Процесс убит, сервис жив** (keep-on-exit): Dart-таймера нет — проверки
  стоят до открытия приложения. Перенос в натив (разбор `.srs` и RPC на Kotlin)
  — отдельная задача, если понадобится.
- **Ложный провал.** Все N случайных хостов из 73 тыс. могут быть мертвы
  сами по себе (домены в реестре блокировок живут долго). Смягчение: N до 5 и
  дефолтная реакция — только уведомление. Ложный провал с реакцией
  `reconnect` стоит переподключения раз за интервал — выбор пользователя.
- **IP-цели** проверяются HTTPS-запросом на адрес: сертификат не сойдётся
  (это считается ответом), но сервер, рвущий соединения без SNI, будет
  «недоступен» — поэтому IP вторичны.
- **`route.final` — не весь маршрут.** Если пользователь направил заблокированное
  отдельным правилом в другой аутбаунд, проверка всё равно идёт через
  `route.final`.
- Трафик: N HTTPS-запросов с телом до 1 КиБ за интервал.

## Verification

- Unit (`test/services/reachability/`):
  - `srs_reader_test.dart` — разбор файлов, собранных портом энкодера ядра
    (v1 legacy-суффиксы, v2+ `\n`, keyword/regex/ip_cidr, логические правила,
    битые данные); фильтр кандидатов (keyword/regex отброшены, зоны без точки,
    маски; geoip — только малые IPv4-диапазоны).
  - `reachability_logic_test.dart` — выборка с ротацией, «хотя бы один из N»,
    вердикт по ответу ядра, ограничение частоты, явный Stop отменяет реакцию,
    Reconnect не воскрешает не-Connected туннель.
  - `reachability_monitor_test.dart` — оркестратор с подменой ядра: успех,
    провал → `resetNetwork` раз за интервал, Stop посреди проверки, событие
    восстановления, `direct-out` → пропуск; extras событий без адресов.
- Разбор реальных `.srs` (05.11.2026, разовый тест): 73 515 суффиксов → 73 515 хостов; 840 диапазонов → 501 IP-кандидат.
- `flutter analyze` — чисто; `tool/l10n/*` (4 чекера) `--strict` — 0 находок.
- Ручная проверка (на устройстве, оператор):
  - [ ] По умолчанию выключено; после включения проверки идут с интервалом;
    при выключенном экране и при остановленном туннеле — нет.
  - [ ] Заблокировать на сервере исходящий трафик к выбранным хостам → провал →
    выбранная реакция; разблокировать → успех и `REACHABILITY_RESTORED`.
