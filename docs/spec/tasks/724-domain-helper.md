## Problem

Чтобы приложение или сервис пошли нужным выходом, пользователь собирает домены
руками: из чужих подборок, документации, догадок. Списки неполные (CDN-редиректы
вроде `release-assets.githubusercontent.com`), слишком широкие (суффикс общего
хостинга `cloudfront.net` уводит в правило чужие сайты) или конфликтуют с уже
существующими правилами, которые стоят выше и перехватывают трафик.

## Behaviour

Вход — кнопка «Подобрать домены» в секции MATCH Inline-правила. Экран помощника:

1. **Кандидаты** — три источника, у каждого хоста метка источника:
   - **Запись приложения** — выбрать приложение(я); помощник запускает запись
     профайлера (028) или берёт уже идущую (START стирает журнал — спросить);
     пользователь делает действие в приложении и жмёт «Готово». Берутся домены
     событий этих пакетов; события без домена (только IP) считаются и
     показываются числом.
   - **Текст** — вставка произвольного текста (подборка из чата, список, URL):
     извлекаются хосты.
   - **Набор правил** — файл из поиска наборов (723): его `domain` и
     `domain_suffix` становятся кандидатами («перенести `.srs` в Inline»).
2. **Нормализация и свёртка** — нижний регистр, punycode, без порта и точки;
   группировка по регистрируемому домену (eTLD+1) по Public Suffix List
   (бандл `assets/psl/public_suffix_list.dat`, MPL-2.0) **с приватной секцией**:
   общие хостинги (`githubusercontent.com`, `cloudfront.net`, `github.io`)
   в суффикс не сворачиваются. Группа предлагается суффиксом, хост, который
   сам публичный суффикс, — только точным доменом.
3. **Покрытие** — по включённым своим правилам в порядке списка (кроме
   редактируемого): Inline — его домены/суффиксы/keyword/regex, `.srs` —
   скачанные файлы. Первое совпадение показывается «правило X → выход»: оно
   стоит выше и может перехватить трафик. Остальные условия правил (порты,
   приложения) не учитываются — это «может совпасть». Пресеты — не в первой
   версии.
4. **Проверка выхода** (по кнопке, только при Connected) — по хосту группы
   запрос через ядро по тегу (`getUrlViaOutbound`, как 721): `direct-out` и
   `route.final`. Итог: «direct работает» / «только через прокси» / «не
   отвечает».
5. **Результат** — группы с галками, переключатель «суффикс / точные домены»;
   «Добавить» дописывает выбранное в поля Domain suffix / Domain (без
   дублей). Выход правила выбирается в редакторе, как обычно.

Сеть — только по действию пользователя: проверка выхода по кнопке, `.srs` — по
выбору файла.

## Non-goals (первая версия)

- Уведомление «Запись для помощника… [Готово]» в шторке.
- Официальные адаптеры (`api.github.com/meta`, индекс F-Droid).
- Учёт пресетов в покрытии.
- Создание правила целиком (помощник наполняет поля редактора).
